# 古诗数据校验与补充 — 设计文档

## 背景

当前项目 `public/poems.json` 包含 70 首古诗，需替换为 200 首新课标古诗（含配读篇目）。用户提供了 200 首诗的题目、年级、作者元数据，但缺少古诗正文内容，需从网络检索并深度校验。

## 数据 Schema 变更

### Poem 接口调整

| 字段 | 旧值 | 新值 |
|------|------|------|
| `id` | `b{book}-{seq}` (如 `b1-01`) | `p{三位数}` (如 `p001`) |
| `grade` | "一年级上/一年级下" | "一年级""二年级"...配读篇目" |
| `unit` | "课文""第X单元" | `""` (空字符串，不再使用) |
| `author` | "李白" | "李白" (不变) |
| `dynasty` | "唐" | "唐" (不变) |

### 作者/朝代拆分规则

用户提供的作者格式为"唐·李白"，需拆分为 `author` 和 `dynasty`：
- "唐·李白" → `author: "李白", dynasty: "唐"`
- "汉乐府" → `author: "汉乐府", dynasty: "汉"`
- "《韩非子·五蠹》" → `author: "《韩非子·五蠹》", dynasty: ""`
- "北朝民歌" → `author: "北朝民歌", dynasty: "北朝"`
- "毛泽东" → `author: "毛泽东", dynasty: "现代"`

### TypeScript 类型更新

- `SourceType` 移除 `'unit'`（不再有按单元抽查）
- `grade` 字段值从"一年级上"变为"一年级"等

## Python 脚本架构

### 文件结构

```
scripts/
  fetch_poems.py          # 主脚本（抓取+缓存+校验+生成）
  poem_meta.py            # 200 首诗元数据
```

### 两阶段流程

**阶段一：抓取+缓存**
1. 读取 `poem_meta.py` 中的 200 条元数据
2. 对每首诗，从古诗文网（gushiwen.cn）检索正文
3. 每首诗单独存为 `.cache/p{序号}.json` 缓存文件
4. 支持断点续跑：已有缓存则跳过
5. 失败项记录到 `.cache/errors.json`，可单独重试

**阶段二：校验+生成**
1. 读取所有缓存文件
2. 执行深度校验规则
3. 输出校验报告（通过/警告/失败）
4. 生成最终 `public/poems.json`

## 深度校验规则

| 校验项 | 规则 | 级别 |
|--------|------|------|
| 字段完整性 | id/title/author/dynasty/grade/text/textType 全部非空 | 失败 |
| 作者匹配 | 网络检索到的作者与元数据中的作者一致 | 警告 |
| 朝代匹配 | 网络检索到的朝代与元数据中的朝代一致 | 警告 |
| 内容非空 | text 数组至少 2 行 | 失败 |
| 标点规范 | 每行以中文标点（，。？！）结尾 | 警告 |
| 字数与 textType 一致 | 五言：去标点后每行 5 字；七言：每行 7 字；其他：不限 | 警告 |
| 重复检查 | 无重复标题+作者组合 | 失败 |
| 交叉验证 | 多来源对比（古诗文网+百度百科），内容不一致时标记警告 | 警告 |

## 前端适配

- `src/types/index.ts`：`SourceType` 移除 `'unit'`
- `src/views/QuizSetupPage.vue`：移除"按单元"选项（如有）
- `src/stores/poem.ts`：`grades` computed 自动适配新数据
- `src/utils/`：distractor/quiz 等按 grade 过滤的逻辑自动适配
- `src/utils/storage.ts`：旧数据迁移处理（poemId 从 `b1-01` 变为 `p001`，需清除旧记录）

## 输出

- `public/poems.json`：200 首诗的完整数据
- `.cache/`：抓取缓存（加入 .gitignore）
- 校验报告：输出到终端
